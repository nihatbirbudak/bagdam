# Eleştirmen bulguları

## Hükümler

- eksiklik: Plan, frontend envanterinin büyük bölümünü (ürün alanları, tier/frekans/gün, ekstralar, iptal/retention, toptan, günlük, politikalar, site içerikleri, localStorage anahtarları) tablo+API+admin+faz düzeyinde karşılıyor; şema ve faz sırası tutarlı. Ancak kendi temel ilkesini (senkron bootstrap) kimlik/abonelik durumuna uygulamıyor: kutu/sepet/uyelik sayfaları isLoggedIn/hasPurchasedSub'ı senkron okur, asenkron hidrasyon FOUC ve cart.js sözleşme kırılması demek — bu kritik. Ayrıca satın alınmış tek seferlik kutunun yönetimi, BoxTemplate↔defaultItems semantiği, F4 DoD'nin dondurulmuş cart.js ile ulaşılamazlığı, cellar/pantry eşlemesi, ana sayfa featured'ında tier kartı ve Cloudflare'in /assets/products.js'i bayatlatması gibi rework üretecek boşluklar var. Planın eklediği kapasite, kurumsal fatura, üretici hikâyesi gibi varlıkların frontend karşılığı yok; şemada kalabilirler ama kapsam/efor yaratmamaları için açıkça 'UI yok' etiketlenmeli. Bu düzeltmeler F0-F3 aralığında yapılırsa plan uygulanabilir.
- sira-rework: Planın faz omurgası (iskelet → donmuş katalog/içerik → admin → auth → motor → PSP → web adaptörü → bildirim) doğru yönde ve UA/BA kalıplarıyla iyi gerekçelendirilmiş; bağımlılık tablosu büyük ölçüde tutarlı. Ancak üç yerde sıra kendi iddialarını çürütüyor: F1 prototipi (sahte checkout, kart formu, 'siparişin alındı') bagdam.com'da herkese açık yayınlamayı DoD yapıyor, F2'de ticari şema motor/PSP tasarımından önce 'donduruluyor' (DELTA/mutable Order ve NON3D B planı bunu zorlayacak) ve F4 DoD'si F9'a ertelenen cart.js değişikliğine gizlice bağımlı. Efor tarafında F7 açıkça hafif, '2 dev 7-8 hafta' F7←F6 bağımlılığıyla çelişiyor (kritik yol ~46 iş günü) ve 'ilk 2 hafta' gerçekte 14 iş günü olup F2'ye F5'in içerik yükü bindirilmiş. Önerilen düzeltmeler (apex gated/coming-soon + staging'de tam site, F2'yi F2a/F2b'ye bölüp dondurmayı F10'a almak, F3'ü F3a ile sınırlamak, F7'yi büyütüp mail bağımlılığını stub'lamak, seed'i sadeleştirmek) uygulanırsa plan rework'süz yürütülebilir.
- sunucu-uyum: Plan, sunucuda gerçekten var olan yığına (Node/PM2/PG14/nginx/Cloudflare, Redis-PHP-Docker yok) oturuyor ve 5010/5011 portları, bellek (9.7 GB boş) ve disk için uygun; same-origin cookie, tek süreç ve lokal dev DB kararları sunucu gerçekleriyle tutarlı. Ancak SSH doğrulaması planın birkaç dayanağını çürüttü: bagdam.com zaten Cloudflare NS'te (NS/DNSSEC adımları gereksiz, MX/SPF sıfır), UA/floovent LE değil Cloudflare Origin CA kullanıyor (LE yenileme 'emsali' yok), nginx'te proxy_cache_path yok, ops script'leri log dosyası değil UA DB tablosunu okuyor ve PostgreSQL oturum zaman dilimi Europe/Istanbul. Bu sonuncusu Prisma'nın timestamp-without-tz varsayılanı ve planın ham SQL `now()` tabanlı kesim/tahsilat kilidiyle birleşince abonelik motorunu 3 saat kaydıran, şema donduktan sonra düzeltmesi pahalı tek KRİTİK bulgu. ÖNEMLİ bulgular (citext migration sırası, products.js edge cache, root deploy anahtarı, Node 20 EOL, KVKK log/yedek politikası, monitoring entegrasyonu) F0-F2 içinde birer satırlık kararlarla kapanabilir; plan bu düzeltmelerle uygulanabilir durumdadır.
